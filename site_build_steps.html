HOW THIS WHOLE SITE WAS BUILT

This is one combined step guide for the main page, both projects, and the four Core Practical cards. It explains the order of work only; it does not include a code section.

Part 1: Build the Main Page

  1. Plan the home page as the central hub for all pages.
  2. Add the site title, short introduction, and moving welcome message.
  3. Create a project section with cards for the café and diary pages.
  4. Create the Core Practicals section with four individual cards.
  5. Give every card a clear topic name, description, and working hyperlink.
  6. Add the animated space background while keeping the text and cards readable.
  7. Finish with a footer and a consistent visual theme.

Part 2: Add the Two Projects

  1. Create the café project page with its name, café image, featured drink, opening hours, and customer story.
  2. Keep the café layout focused on the menu feeling, atmosphere, and visit details.
  3. Create the personal diary project page with a title, mood area, diary entries, and memory images.
  4. Add the diary date field and writing area so a visitor can save daily entries in the browser.
  5. Add a back-to-home link and an internal link on both project pages.

Part 3: Combine the Four Core Practicals

  1. Add Practical 01 for Formatting Styles and Headings, including the six heading levels and text styles.
  2. Add Practical 02 for Font Styles and Image Tag, including different fonts, images, and a photo gallery.
  3. Add Practical 03 for Marquee, including moving text, an image, and a hyperlink.
  4. Add Practical 04 for Other Tags, including paragraphs, line breaks, dividers, and preformatted content.
  5. Keep each practical as its own linked card so the home page stays easy to navigate.
  6. Add a separate step guide button where a practical needs extra explanation.

Part 4: Push and Deploy with GitHub Pages

  1. Sign in to GitHub and create a new public repository with a clear name such as little-life-logs.
  2. Open the project folder in VS Code and open its terminal.
  3. Initialize Git in the project folder and check which files are ready to be tracked.
  4. Add the project files to Git, then create the first commit with a message such as Build practical website.
  5. Connect the local project to the GitHub repository using the repository URL.
  6. Push the project to the main branch on GitHub.
  7. Refresh the GitHub repository page and confirm that all HTML files are visible.
  8. In the repository, open Settings, choose Pages, and select Deploy from a branch.
  9. Select the main branch and the / (root) folder, then click Save.
  10. Wait for GitHub Pages to publish the site. The public address usually follows https://your-username.github.io/repository-name/.
  11. For later changes, repeat the add, commit, and push steps. GitHub Pages will rebuild the site automatically.

Keep index.html in the repository root because it is the GitHub Pages entry page. Before pushing, check that passwords, private keys, personal tokens, and other secret information are not inside the project files.

Part 5: Connect the Pages

  1. Check that the main page links to both projects and all four practical pages.
  2. Check that every page links back to the main page.
  3. Add internal links where a page has multiple sections.
  4. Use the same naming, color direction, spacing, and typography across related pages.

Part 6: Check the Deployed Site

  1. Open the GitHub Pages URL in a browser, not with the VS Code Code Runner.
  2. Click every project and Core Practical card from the deployed home page.
  3. Confirm that all links use the existing relative filenames and do not point to local computer paths.
  4. Refresh the diary page and confirm its browser-saved entries still work on the deployed site.
  5. If a change does not appear immediately, wait for the Pages deployment to finish and refresh the browser.

Part 7: Final Testing

  1. Open the main page in a browser instead of using Code Runner for HTML.
  2. Open each project and practical card from the home page.
  3. Test every back link and internal link.
  4. Check that images load and have useful alternative text.
  5. Test the marquee, diary writing, accordion entries, and animated backgrounds.
  6. Resize the browser to confirm the cards and pages remain readable on mobile.

The four Core Practical pages remain separate for submission, while this page combines their build process with the main page and project workflow.
